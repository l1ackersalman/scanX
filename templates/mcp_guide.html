How it works

  1. ScanRun a scan of your domain from the Overview.
  2. ConnectClick Connect above and paste the setup into your AI client.
  3. AskAsk your agent for an attack-vector report. It reads your scan data through scanX's tools.
  4. ReviewThe finished report appears on Reports, ready to read or download.

scanX speaks the Model Context Protocol (MCP), an open standard that lets AI apps call tools. Your agent runs on your side with your own AI subscription; scanX only answers its tool calls. scanX never contacts an AI provider and needs no AI API key.

Set up your AI client

Choose your client. {% if new_token %}Your new token is already filled in.{% else %}Replace YOUR_TOKEN with the token you get from Connect.{% endif %} Restart the client after changing its settings.

{% with token=new_token.token|default:"YOUR_TOKEN" %}
Claude Code terminal

Run once in a terminal:

claude mcp add --transport http {{ server_name }} {{ endpoint_url }} --header "Authorization: Bearer {{ token }}"

Check it with claude mcp list — scanx should show as connected.

Cursor ~/.cursor/mcp.json

Cursor Settings → MCP → Add new MCP server, or edit ~/.cursor/mcp.json:

{
  "mcpServers": {
    "{{ server_name }}": {
      "url": "{{ endpoint_url }}",
      "headers": { "Authorization": "Bearer {{ token }}" }
    }
  }
}
VS Code (GitHub Copilot agent mode) .vscode/mcp.json

Create .vscode/mcp.json in your workspace (or run MCP: Add Server):

{
  "servers": {
    "{{ server_name }}": {
      "type": "http",
      "url": "{{ endpoint_url }}",
      "headers": { "Authorization": "Bearer {{ token }}" }
    }
  }
}
Claude Desktop needs Node.js 18+

Settings → Developer → Edit Config, then add this to claude_desktop_config.json. It uses the small mcp-remote bridge, downloaded automatically by npx:

{
  "mcpServers": {
    "{{ server_name }}": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "{{ endpoint_url }}", "--header", "Authorization:${SCANX_AUTH}"],
      "env": { "SCANX_AUTH": "Bearer {{ token }}" }
    }
  }
}

Fully quit and reopen Claude Desktop. On Windows, if npx is not found, use "command": "cmd" and put "/c", "npx" at the start of args.

Any other MCP client

Add a remote server using the Streamable HTTP transport:

  • URL: {{ endpoint_url }}
  • Header: Authorization: Bearer {{ token }}

Clients that only support local (stdio) servers can use npx -y mcp-remote as shown for Claude Desktop.

REST API — for agents without MCP

The same tools over plain HTTPS and JSON, with the same token from Connect. Use it from your own agent code, LangChain, n8n, Zapier, a GPT Action, or curl.

{% with token=new_token.token|default:"YOUR_TOKEN" %}
  • GET {{ api_base }}tools — every tool with its JSON Schema, ready to hand to any model's function calling.
  • POST {{ api_base }}tools/<name> — run a tool; the JSON body is its arguments. Answers {"data", "meta"}; errors come back as HTTP 422 with meta.message.
  • GET {{ api_base }}openapi.json — OpenAPI 3.1 spec; import it into GPT Actions, Postman or an OpenAPI agent toolkit.

Try it

curl -s {{ api_base }}tools/list_scans \
  -H "Authorization: Bearer {{ token }}" \
  -H "Content-Type: application/json" \
  -d '{"status": "completed", "limit": 5}'

Minimal agent loop (Python, any AI provider)

Fetch the tools, give them to your model as functions, and forward each call to scanX:

import requests

SCANX = "{{ api_base }}"
HEADERS = {"Authorization": "Bearer {{ token }}"}

tools = requests.get(SCANX + "tools", headers=HEADERS).json()["data"]
# -> give `tools` (name, description, input_schema) to your model as functions

def call_scanx(name, arguments):
    r = requests.post(SCANX + "tools/" + name, json=arguments, headers=HEADERS)
    return r.json()          # {"data": ..., "meta": {...}} - send back to the model

# Finish with: call_scanx("save_report", {"scan_id": ..., "title": ..., "content": ...})

Reports saved through the API show on Reports as “(REST API)”.

Ask for a report

Once connected, talk to your agent normally. It decides which scanX tools to call. Examples:

  • Using scanX, analyse my latest completed scan, map the possible attack vectors and save an attack vector report.
  • Which hosts are new since the previous scan, and do any of them look like admin, staging or login pages?
  • List the technologies scanX found and flag any that disclose a version number.
  • Find hosts with CNAMEs pointing to third-party services that could be at risk of subdomain takeover.

Built-in prompt: attack_vector_report

scanX ships a ready-made prompt that walks the agent through a full analysis — exposed panels, dev/staging hosts, directory listings, version-disclosing tech, takeover candidates — maps each finding to MITRE ATT&CK, rates it, and saves the report. In Claude Code type /mcp__{{ server_name }}__attack_vector_report; in Claude Desktop use the + menu → scanx. Other clients list it under MCP prompts.

Reports saved by agents are listed on Reports with the agent's name, and can be downloaded as Markdown.

Every tool answers in the same shape — {"data": …, "meta": {"status", "message", "total", "hasMore", "nextCursor"}} — and long lists come in pages. Only save_report writes anything; nothing can start, stop or delete scans.

Security and privacy

  • One organization per token. A token can read only the scans of the organization you chose, and save reports only for them.
  • Treat the token like a password. Anyone with it can read that organization's scan results. scanX stores only a hash of it, so a lost token can't be shown again — connect again to get a new one.
  • Disconnect any time under Your connections (in the browser you connected from). The token stops working immediately.
  • Read-only analysis. Agents cannot start scans, change data or reach your hosts through scanX. The built-in prompt also tells them not to probe the hosts themselves.
  • Your AI provider sees the data your agent reads. Scan results pass through the AI client and model you use, under that provider's terms.
  • Only connect agents to organizations and domains you are authorized to assess.

Troubleshooting

“401 / Missing or invalid token”

The token is wrong, was disconnected, or the header is missing. Check the header reads exactly Authorization: Bearer sx_…, or connect again for a new token.

The agent doesn't see any scanX tools

Fully restart the AI client after editing its config. In Claude Code run claude mcp list; in Cursor check Settings → MCP for a red status dot and its log.

“Scan … is running / failed, not completed”

Only completed scans have host data. Wait for the scan to finish on its scan page, or ask the agent to use list_scans with status completed.

Claude Desktop: “spawn npx ENOENT”

Node.js isn't installed or not on the PATH. Install Node.js 18+ and restart, or use the Windows cmd /c form shown above.

Opening the server URL in a browser shows an error

That's expected — /api/mcp is for AI clients, not browsers. Use the setup snippets instead.
